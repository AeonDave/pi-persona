# Quality review — 2026-09-04

## Decision

Release-ready for the reviewed scope. The review found and corrected real durability, concurrency,
filesystem-boundary, and Pi-facing output defects. No known release blocker remains.

Baseline: `main` at `3af5913`, including the Exocom ledger, stable identity, generic telemetry, and
post-1.12.2 fixes. The reviewed candidate was released as commit `38fb5b2`, tag `v1.13.0`.

## Scope

- Exocom claim/ask/answer/decline/wait/progress/release semantics and cross-process ledger.
- Artifact spill transport and Windows named-pipe/path behavior.
- Prompt, tool-result, follow-up, renderer, and active-tool output presented to Pi.
- Top-level Exocom identity bootstrap and rename-safe routing; sub-agent naming remains supervisor-owned.
- Stringified `delegate.tasks` compatibility.
- Telemetry ownership and retry boundaries.
- Architecture, documentation, regression coverage, type safety, and package contents.

## Corrected findings

1. A partial JSONL append could poison the ledger tail and make a later successful commit disappear
   on replay. Failed appends now roll back under the lock; crash tails are repaired conservatively,
   complete records without a final newline are preserved, unknown tails fail closed, and the hard
   size ceiling cannot be bypassed by recovery.
2. An empty claim `write_set` consumed ownership capacity without owning a path. Wire validation,
   reducer validation, and the TypeBox tool schema now all require at least one path.
3. Pending asks could overfill and duplicate the model-facing surface. Pi now receives one complete,
   fenced next question plus an omitted count; the tool gate repeats only the `ask_id`.
4. Artifact validation had pathname TOCTOU and cleanup gaps. Reads now use a held identity-checked
   descriptor, receiver snapshots use unpredictable exclusive destinations, and received snapshots
   share the bounded cleanup policy.
5. A planted `artifacts` junction/symlink could redirect spill reads and writes outside Exocom. The
   artifact root is now checked as a real directory and its identity is checked across operations.
6. A transient Exocom registry read could abort `before_agent_start`. Peer awareness now fails open
   while ledger uncertainty still fails closed for mutation/delegation.
7. A durable ask/answer whose immediate wake failed looked like an ordinary success and could expose
   peer-authored NACK text. Tool output now explicitly says `ledger committed; peer wake deferred`
   without reflecting the remote error.
8. Failed Exocom work tools rendered with success chrome, and Exocom tools could remain active after
   shutdown. Renderers now honor `isError`; active tools follow plane/capability lifecycle.
9. JSON-decoded `delegate.tasks` bypassed inner field validation and could crash later on values such
   as a numeric `role`. Decoded scalar, list, brief, isolation, MCP, and timeout shapes are validated
   before use.
10. `exocom_wait` had an answer-between-reads race that falsely returned `no pending outbound ask`.
    It now decides from one initial snapshot and closes the race after waiter registration.
11. A failed post-registration ledger read left a hidden wait timer that could wake Pi after the tool
    had already failed. The waiter is now disarmed on that error path.
12. A retained qualified target stopped routing after its peer changed call-sign because resolution
    compared the whole display token. The 96-bit session suffix is now the routing identity, the
    readable prefix is presentation only, and an improbable suffix collision fails closed.
13. Top-level Pi instances could remain `unnamed`/persona-labelled for several turns. On the first
    unconstrained task turn, the system prompt now instructs the existing model to invent a
    task-derived call-sign and call `exocom_name` before prose or any other tool. There is no name
    catalog and no extra model call; an inbound ask still has priority and naming resumes immediately
    after settlement. This ordering is behavioral prompt protocol, confirmed by the live runs below,
    not a hidden runtime-generated name.
14. A persona denying both `exocom_answer` and `exocom_decline` could still advertise itself and then
    be permanently frozen by a durable inbound ask it could not settle. Exocom admission now requires
    at least one callable closer; targeted tool denies remain effective independently.
15. Wait-notice cleanup matched `ask_id` by substring. An id `a` could collide with `a1`, and peer
    prose containing the text could discard another notice. Cleanup now parses only exact ids from
    trusted extension-owned metadata lines.
16. Pi-facing target guidance described mutable names but omitted rename stability, and one ask error
    incorrectly requested the exact "name". Tool schema/results now identify the qualified target and
    explain that its session suffix survives a rename.
17. A persona could deny `exocom_name` yet receive a mandatory first-action naming instruction on
    every turn. Prompt composition now checks the same live per-tool capability gate; the instance may
    remain a protocol participant under its placeholder/persona label without being ordered to call a
    denied tool.
18. Transport accepted a retained pre-rename target by session suffix, while telemetry still compared
    the whole current token and silently omitted the successful `message.sent` edge. The projection now
    mirrors suffix routing and emits no speculative edge if more than one live peer matches.
19. Exocom discovery was locked to the process cwd, so a full Pi with a separate document corpus could
    not join the project team. Bare `--exocom` now keeps the workspace scope, while exact
    `--exocom=Ab0T` resolves a persistent four-character Base62 alias to the same full workspace id.
    Alias publication is atomic and uses case-fold-safe filenames; collisions probe without
    overwriting or recycling reservations, and malformed/unknown codes fail closed.
20. A joined Pi could otherwise make unrelated repository-relative paths look mutually exclusive.
    Every peer now advertises its actual safe workspace identity; foreign members retain messaging and
    durable ask settlement but cannot claim the joined workspace's paths. The tool gate and signed-frame
    receiver both enforce that boundary. Pi-facing surfaces expose bounded labels/codes, never `cwd`.
21. An invalid join code in headless/RPC mode disappeared into a TUI notification that had no consumer.
    Startup still degrades safely to normal Pi, but the failure is now emitted on stderr.

## Pi-facing behavior

- The ledger is authoritative; signed semantic frames are immediate-wake signals only.
- Postcard chat remains prompt-guided and non-authoritative. `exocom_send` neither claims work nor
  resolves an ask.
- Pending peer text and evidence remain attributed and fenced as untrusted input.
- Registry-only failures do not erase the base/system prompt. Ledger failures block writes and
  delegation rather than guessing ownership.
- Wait is non-blocking and produces one retained-answer/timeout follow-up without a lost-answer or
  ghost-wake window in the tested paths.
- The first free task turn instructs an unnamed top-level Pi to name itself before any other action.
  Sub-agent call-signs remain parameters chosen by the supervisor's delegation protocol, not Exocom
  identities.
- Qualified targets remain routable across display-name changes; inbound attribution always uses the
  receiver's current authenticated registry view.
- A peer can be a full Pi in another workspace. The selected scope controls Exocom transport and ledger
  state, while `same workspace`/`external workspace` identifies which files that Pi can actually inspect.

## Boundaries and non-blocking debt

- Prompt grammar is sufficient for postcard etiquette; atomic write ownership and mandatory ask
  settlement require the runtime ledger/gate. This remains cooperative same-user coordination, not
  OS authorization: another local process with the same privileges can edit the workspace or ledger.
- Telemetry remains a generic, producer-scoped v2 observer contract for pi-persona-flow and future
  plugins; it is not an exclusive flow protocol and carries no prompt/task/model-output bodies. An
  Exocom join scope does not replace telemetry's actual-cwd workspace identity.
- Host-session transient retry/backoff remains owned by Pi. pi-persona does not parse `N/INF` or
  jitter notation from prompts; its provider fallback, MAGI model retry, notifier retry, and
  delegation-loop veto are separate bounded mechanisms.
- `test/unit/telemetry/parity.test.ts` pins one inert sanitizer drift for non-finite values. Current
  producer/parser callers normalize or reject that input before it can persist or cross the contract;
  aligning the independent flow consumer remains cross-repository cleanup, not a live defect here.
- The pending-ask gate is intentionally hard. A model that uses only postcard chat has not entered
  the ledger protocol and receives only the older prompt-guided collaboration semantics.
